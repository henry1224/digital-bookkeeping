Temuan Prioritas

Urut dampak tertinggi
1

Wireframes kosong total — docs/04-design/wireframes/

Folder sudah dibuat sejak 10 Jul tapi 0 file. Halaman baru (Master Data, Finance, Logistik, Reporting) dibangun tanpa rujukan layout tervalidasi, berisiko UI antar developer/agent berbeda-beda — persis kekhawatiran "tampilan berubah-ubah".

AksiBuat minimal 1 wireframe per template (list, form, detail, report) sesuai design-system.md §Template Layout sebelum modul transaksi berikutnya digarap.
2

Token warna dokumen vs kode sudah divergen

docs/04-design/design-system.md mendefinisikan primary #1E40AF (biru). Implementasi nyata di resources/css/app.css memakai hsl(168 76% 36%) (emerald/teal). Warning/danger/border juga tidak match. Dokumen ini sudah jadi sumber kebenaran palsu.

AksiUpdate tabel Design Tokens di design-system.md agar merefleksikan CSS variable aktual (emerald/teal), bukan sebaliknya — karena kode sudah dipakai di halaman Login & Outlets.
3

Kamus data belum mencakup 11 dari 27 tabel inti MVP

docs/02-database/data-dictionary.md tidak punya definisi kolom untuk users, roles, permissions, item_groups, unit_of_measures, suppliers, bank_accounts, recipes, recipe_ingredients, stock_counts(_lines), stock_adjustments(_lines) — padahal migration & model sudah ada untuk sebagian (mis. Supplier, Item, UOM).

AksiTambah 11 section baru mengikuti pola kolom yang sudah ada di file yang sama.
4

Dua dokumen ber-ID "ADR-001" yang berbeda topik

docs/01-architecture/adr-001-keputusan-fondasi.md (Keputusan Fondasi) dan docs/01-architecture/adr/001-stack-laravel-inertia-vue.md (stack Laravel) sama-sama diberi nomor 001 di lokasi berbeda.

AksiKonsolidasikan semua ADR ke folder adr/ dengan penomoran berurutan tunggal (mis. geser fondasi jadi ADR-005 atau gabung).
5

ADR-002 (moving average) masih berstatus "Proposed"

Padahal review-action-plan.md dan CLAUDE.md sudah mengunci moving average sebagai keputusan final MVP. Status ADR belum diupdate ke "Accepted" — inkonsisten antar dokumen.

AksiUbah status jadi Accepted, tautkan ke adr-001-keputusan-fondasi sebagai rujukan penguncian.
6

Kontrak API sangat minim — hanya 10 endpoint POST

docs/03-api/openapi.yaml cuma mendefinisikan create untuk 8 resource. Tidak ada GET/list, master data (outlet, item, supplier, account, user), stock opname, recipe, maupun report (Laba Rugi/Neraca/Trial Balance).

AksiTambah minimal GET list + detail per resource utama, dan schema report sebelum modul reporting digarap.
7

State machine & user-flow belum cover transaksi inti

State machine ada untuk manual-journal, payment-request, period-closing/reopen, purchase-order, stock-adjustment — tapi tidak ada untuk daily_sales, receiving, purchase_request (outlet request), dan stock_usage/opname, walau ini transaksi harian utama MVP.

AksiTambah 4 state machine yang hilang di docs/05-business-rules/state-machines/.
